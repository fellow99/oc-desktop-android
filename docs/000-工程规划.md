## 1. 项目概述

### 1.1 一句话定义

`oc-desktop-android` 是一个 **Kotlin Android 应用**：`MainActivity` 启动后由 `aosp-node-bridge` 在**应用自己的进程内**拉起 Node（版本由 `node-runtime` 包锁定），Node 侧加载 **opencode v2.1.2 的 stock CLI 产物**并以 `serve` 语义常驻（同源托管 `/api/*`、`/auth/*` 与内嵌 Web UI，SSE 推事件）；主界面是一个**系统 WebView**，先显示应用内加载页，探活成功后 `loadUrl("http://127.0.0.1:<port>/?auth_token=…")` 加载**由本机服务渲染的**标准 opencode Web UI —— 同源、零 CORS、零 JS 注入桥、零内嵌浏览器内核。在此之上提供 **Git 能力**（isomorphic-git 插件）与 **pnpm 能力**（进程内 pnpm），功能面、补丁面、插件面对标 `oc-desktop-ark`。

## 2. 背景与依据

### 2.1 Android 上的路线选择

| 路线 | 形态 | 判断 |
|---|---|---|
| **A：进程内 `dlopen` + `node::Start`**（**选定主线**） | `aosp-node-bridge` 在应用进程内跑 Node，WebView 加载 `127.0.0.1` | ✅ 与 ark 同构；JNI 壳最薄；数据面零 IPC；消费方零 C++ |
| **B：`:node` 独立进程**（**可选加固，非默认**） | `android:process=":node"` 的 Service 承载 Node | 🔶 唯一可「崩溃后重启 Node」的形态；代价 IPC + 内存翻倍；Phase 3 评估 |
| C：子进程 exec 自带 node ELF | 改名/打包技巧 | ❌ Play 政策风险、noexec 趋势、体积翻倍 |
| D：WebView 内 JS 引擎（QuickJS/Hermes） | 不是 Node | ❌ 无 fs/http/原生模块 |
| E：云端/远端 opencode | 网络依赖 | ❌ 违背本地离线定位 |

**结论**：A 与 `oc-desktop-ark` 完全同构，文档、契约、补丁、插件可最大限度复用；B 登记为可选加固。崩溃语义与 ark 相同：**进程内 Node 崩溃 = 应用崩溃（终态）**，UI 只能给「请重启应用」。

### 2.2 opencode v2.1.2 的结构性事实（✅ 上游文档/源码核实，与 ark §2.2 同源）

**(a) 服务化入口**：`opencode serve [--hostname|--port|--cors]`（官方 `server.mdx`）→ 常驻 HTTP 服务；OpenAPI 3.1 规范在 `GET /doc`；全局健康 `GET /global/health`；SSE 事件 `GET /event`（全局）与会话级事件流。TUI 只是其中一个客户端 —— **桌面形态 = 独立客户端连本机服务**，这正是本工程与 ark 的复用基座。

**(b) 密码必填**：`password` 缺失即失败；取值优先 `OPENCODE_SERVER_PASSWORD` / `OPENCODE_PASSWORD` 环境变量 → 否则进程内随机。本工程始终显式注入（§5 D6）。

**(c) UI 与 API 同源托管**：`/api`、`/api/*`、`/auth/*`、`/openapi.json` 交给 API，其余路径回落内嵌 UI（SPA，`index.html`）；UI 资产是内嵌 brotli 归档 `app-archive.bin`，非 SEA 运行时从 `OPENCODE_NODE_ASSETS_DIR` 读取。⇒ **零前端工程、零自定义协议、零 preload 桥、零 CORS**：WebView 只要加载 `http://<host>:<port>/`，UI 与 API 即同源。

**(d) 鉴权三通道**（`packages/server/src/middleware/authorization.ts`）：① `Authorization: Basic base64("opencode:<password>")`；② **URL 查询参数 `?auth_token=…`**；③ 会话 Cookie `opencode_session_<port>`（仅同源）。

**(e) 前端原生支持「启动即带凭据」**：`packages/app/src/entry.tsx:81` 读取 `?auth_token=` 作为连接密码，随后 `clearAuthToken()` 从地址栏抹除；之后所有请求由 SDK 自动加 Basic 头。**这条 (e) 是本工程鉴权方案的地基**（与 ark 完全一致）：WebView 只需一次正确的首屏导航，之后不再依赖任何宿主注入能力。

### 2.3 运行时事实（`aosp-node-bridge` / `aosp-node-runtime`，✅ 库文档 + 探针记录）

| 事实 | 值 | 对本工程的要求 |
|---|---|---|
| 双包 | `io.github.fellow99:node-bridge:0.2.0`（API+引导件）+ `node-runtime:<Node版本>`（引擎 AAR） | 版本在 `build.gradle.kts` **钉死**，不floating |
| 引擎 | `libnode.so`（ET_DYN、无 PT_INTERP、导出 `node::Start`）+ `libc++_shared.so`（runtime 包单点供给） | `runtime.lock.json` 锁 SHA-256/ELF 门禁；`tools/provision.mjs --check` 校验 |
| 加载 | `System.loadLibrary` 先行，`dlsym("_ZN4node5StartEiPPc")`；裸名/绝对路径皆可用 | 由库处理，宿主零 C++ |
| `node::Start` | **每进程一次**，无优雅停止 | 崩溃终态；错误页文案「请重启应用」 |
| 状态机 | `Idle → Starting → Running → Exited/Failed`（Kotlin `StateFlow`） | 启动编排订阅状态 + marker 双判据 |
| 启动 API | `rt.start(NodeRuntimeOptions(entry, appEntry, env, execArgv))`；`execArgv` 默认必须为**空**（18 时代默认 flag 曾致 rc=9，✅ R2 教训） | 本工程不传 `--jitless` 进生产 |
| 宿主能力桥 | `rt.host.register(name){json}` 先注册**再** start；Node 侧 `host.invoke(name, json)`；未注册如实报错 | 权限/SAF 选择器/外链/通知走这条（§6） |
| 载荷 | 库自带 `bootstrap.js/host.js/selfcheck.js` 随 AAR assets，**首启物化到 `filesDir/node-bridge`**；业务载荷由本工程自管 | 业务载荷（opencode 产物）必须解包到 `filesDir`（§5 D7） |
| 日志/崩溃 | logcat + 文件 + `logs()` + `lastCrash()` + `/facts` 自检 | 诊断面板直接消费；判据不依赖 logcat |
| JIT | 🔶 Android 15(API36) 真机 JIT+WASM ✅（R2：hotLoop 17.8/15.4 ms，targetSdk 36 与 28 双 flavor 全过） | 新引擎 24.22.1 上 P0-K 复验；`--jitless` 仅诊断（WASM 全废 ⇒ fetch 废） |
| 16 KB 页 | 引擎构建期 `-z max-page-size=16384`；bring-up 18.20.4 产物 4 KB 不合格（✅ R1） | 锁值校验含对齐门禁；24.22.1 已按 r28 自建（✅ lock） |
| 网络 | 引擎与应用同进程 ⇒ 无跨进程网络隔离问题；Android 无 OHOS 式 ACL | 无 ACL 申报；风险面=平台策略（§10） |
| 子进程 | FAQ 明说不支持 spawn Node；`/system/bin/sh`（toybox）存在 | `bash` 工具降级策略见 §8.2；git/pnpm 一律进程内 |

### 2.4 与 `oc-desktop-ark` 的差异与平移性（决定哪些结论不能照抄）

| # | 维度 | oc-desktop-ark（OHOS） | 本工程（Android） | 平移性 |
|---|---|---|---|---|
| 1 | 宿主语言/UI 框架 | ArkTS + ArkUI | Kotlin + Android View/Web | 🔁 换实现，语义同构 |
| 2 | 只读载荷 | `resfile/` 真路径可直读 | `assets/` 非路径 ⇒ 必须解包 | ❌ **不可平移**（D7 改自解包） |

| 4 | 渲染组件 | ArkWeb `Web` 组件 | 系统 WebView + `networkSecurityConfig` | 🔁 换 API；必备项等价 |
| 5 | loopback 访问 | ⚠️ 曾有进程隔离争议（探针裁决） | WebView 加载 `127.0.0.1` 为常规做法；明文需显式放行 | ✅ 更稳（P0-D 复验） |
| 6 | 后台常驻 | 封死 | 前台服务可行 | ✅ **能力增量**（D15） |
| 7 | 崩溃恢复 | 不可 | 进程内同样不可；`:node` 进程可 | ✅ 可选增量（D1/B 路线） |
| 8 | 宿主能力桥 | `HostBridge`（ArkTS） | `rt.host.register`（Kotlin，JNI 直调） | 🔁 能力清单更宽（Intent/SAF/通知） |

## 3. 目标与原则

### 3.1 v1 目标（可逐条打勾）

1. **能起**：APK 可安装、可启动，进入窗口，**无白屏、无闪退**；加载页 → 主界面有明确阶段文本。
2. **能对话**：新建会话 → 发消息 → **流式**回复 → 工具调用可视化 → 重启应用后会话仍在。
3. **能配模型**：Settings › Models 可填 API Key（凭据落沙箱），可切换 provider/model。
4. **能用工具**：文件读写/编辑/列目录/搜索（上游工具链）；`bash` 工具按 §8.2 降级策略工作。
5. **能选工作区**：沙箱工作区管理（多项目目录）+ SAF 导入/导出；服务端以所选目录为项目根。
6. **能用 Git**：isomorphic-git 插件，diff/分支/提交/凭据在 UI 内可用（对标 ark 108）。
7. **能用 pnpm**（本工程新增）：进程内 `pnpm install/add/run/remove/list`，store 落沙箱，默认忽略脚本；UI 内可见输出与失败原因。
8. **失败可见**：任何一步失败都在 UI 上留下**可截图**的文字（阶段 + 原因 + 日志尾 + 「重启应用」提示）。
9. **能分发**：侧载 APK 全流程可复现；Play AAB 评估结论落档（含 PAD 体积方案取舍）。

### 3.2 设计原则

| 原则 | 展开 |
|---|---|
| **一切经 HTTP** | WebView 与 Node 只通过同源 HTTP/SSE 通信；不加 JS 注入桥、不引入 IPC 载体 |
| **壳薄、契约硬** | Kotlin 只做「启动 / 观测 / 宿主能力 / 渲染」；业务全在 Node 侧 |
| **不改上游** | 优先现成机制（`OPENCODE_*` env、条件变体、同名顶替）；补丁必须**幂等、可反向** |
| **不隐藏平台真相** | 终端不可用、搜索降级、pnpm 忽略脚本等如实上报，不静默降级 |
| **判据可证伪** | 每条验收写成「能观测到 X」；不用「看起来好了」 |
| **谁写谁读** | 需要 Node 读的文件由 Node 自己写/解包；Kotlin 不解业务载荷 |

## 5. 核心决策

> 决策登记：D1 运行时=Maven 双包；D2 服务端=stock CLI bundle；D3 端口=OS 分配+嗅探+marker；D4 渲染=系统 WebView；D5 网络=loopback 单实例；D6 鉴权=auth_token 首选+密码持久化；D7 载荷=assets 自解包；D8 SQLite=node:sqlite 零补丁；D9 环境契约；D10 补丁=自有 patches/v2.1.2 对标 ark 五件套；D11 插件=L1 本地+三个壳插件；D12 Git=isomorphic-git；**D13 pnpm=进程内（新增，✅ 推荐档位已确认）**；D14 工作区=沙箱+SAF；D15 后台=可选前台服务；**D16 标识与版本（✅ 已确认）**。

### 5.1 D1 运行时：Maven 双包（`node-bridge` + `node-runtime`）✅

- `build.gradle.kts`：`implementation("io.github.fellow99:node-bridge:0.2.0")` + `runtimeOnly("io.github.fellow99:node-runtime:<lock.active.node>")`，**版本钉死**；升级 Node = 换这一个依赖 + 更新 `runtime.lock.json` 引用（桥不用重编 —— 运行期符号契约咬合）。
- 构建期门禁：`node tools/provision.mjs --check`（借库仓工具或本工程镜像脚本）校验 AAR 内 `libnode.so` SHA-256/ELF 八项门禁/16 KB 对齐 = 锁值；不符**硬失败**。
- **不写 C++**：消费方零原生代码（库承诺）；`libs/` 不得出现本工程自放的 `.so`。
- 进程模型：默认**应用主进程内**（与 ark 一致）；`:node` 独立进程作为 Phase 3 可选加固（收益：Node 崩溃可重启；代价：IPC + 内存），启用与否不影响其余设计。

### 5.2 D2 服务端：stock CLI bundle + `serve` 语义 ✅

产物构建（host 侧，可复现，与 ark 完全同链）：

```bash
cd ../opencode                                   # 共用 submodule（§9 守卫）
node ../oc-desktop-android/scripts/apply-patches.mjs   # 幂等补丁 + 基线守卫
bun install --os=* --cpu=*
OPENCODE_NODE_TARGET=node24 bun run --cwd packages/cli script/build-node.ts --target=linux-arm64 --bundle-only
# → packages/cli/dist-node/opencode.mjs + assets/**（含 app-archive.bin）
```

- `--bundle-only`：不产 SEA；`OPENCODE_NODE_TARGET=node24` 由补丁 0001 注入（对齐 24.x 引擎；lock 24.22.1 仍属 node24 目标）。
- `--target=linux-arm64` 只为走通收集；JS 平台无关，原生件随后裁剪/打桩。
- 宿主入口 `payload/opencode-server.js` 五步职责**照搬 ark 同名文件**（env → chdir → stdout 嗅探 → argv → import + 异常兜底），仅 marker/env 值按本工程调整；随载荷投放并被 `NODE_BRIDGE_ENTRY` 解析。

### 5.3 D3 端口与就绪（可证伪）

| 判据 | 观测点 |
|---|---|
| 服务端已监听 | `filesDir/payload/server.ready.json` 存在且 `port>0`（Node 侧原子写） |
| API 可用 | Kotlin 侧 `HttpURLConnection` 探活 `GET /global/health`（带 Basic）200 |
| UI 可用 | WebView `onPageFinished` 且首屏非错误页 |
| 失败可见 | marker 超时 / `onReceivedError` / `lastCrash()` 非空 → 错误页（附日志尾） |

常量端口只用于诊断（`adb forward`）；产品路径**必须** `--port 0`（`EADDRINUSE` 会以未捕获异常带走整个应用）。单实例：`launchMode="singleTask"`。

### 5.4 D4 渲染：系统 WebView（唯一通道）✅

| 项 | 结论 |
|---|---|
| 必备配置 | `settings.javaScriptEnabled=true`、`domStorageEnabled=true`（缺则 SPA 首屏崩）、`databaseEnabled=true` |
| 明文 HTTP | `networkSecurityConfig` 对 `127.0.0.1`/`localhost` 显式 `cleartextTrafficPermitted="true"`（Android 9+ 默认禁明文；🔶 库 §6.3） |
| 注入 | **不预设**；仅当 P0-E 发现能力缺失才用 `evaluateJavascript` 兜底（保持零注入优先） |
| 导航围栏 | `WebViewClient.shouldOverrideUrlLoading` 只拦主 frame：本机服务内导航放行，外链交系统浏览器/Custom Tab |
| 后退键 | 首屏成功 `webView.clearHistory(true)`；`OnBackPressedCallback`：WebView 可后退则 `goBack`，否则退出确认 |
| Service Worker | UI 生产构建会 `register("/sw.js")`；不支持则无害失败，不作判据 |
| 必测八项 | localStorage / IndexedDB / fetch / SSE(EventSource ≥60s) / crypto.subtle / blob worker / wasm / CSP（含内联主题 sha256） |

### 5.5 D5 网络：loopback + 单实例

- 服务端 `--hostname 127.0.0.1`；WebView 加载 `http://127.0.0.1:<port>/`。Android 上无 ark §5.4 的「进程间网络隔离」争议（同进程渲染），但保留 P0-D 探针与「局域网回退路线 B（`0.0.0.0`+LAN IP+密码+显式提示）」备案，触发条件=特定 ROM 拦截 loopback。
- `NO_PROXY`/`no_proxy` 追加 `127.0.0.1,localhost,::1`（避免系统代理劫持本机流量）；`ACCESS_NETWORK_STATE` 仅用于诊断面板展示连通性。
- 不启用 mDNS；不做 Host/Origin 改写补丁（同源天然一致）。

### 5.6 D6 鉴权与凭据 ✅（与 ark 同构）

- **首选 `?auth_token=<base64("opencode:"+PWD)>`**：WebView 首屏一次导航；前端读取后立即抹参数并持久化连接；之后 SDK 自动 Basic（§2.2 e）。
- **备选** 配对 Cookie（`/auth/connect/<code>`）与兜底 Basic —— 仅当 P0-F 判定首选不可用时启用。
- 密码生命周期：首启生成 32B base64url → `filesDir/connection.json`（`MODE_PRIVATE`）跨启动复用；轮换仅在用户主动重置/文件损坏；密码只经 env 交给 Node（`OPENCODE_SERVER_PASSWORD`），**不写日志**；诊断面板对 URL 一律 `?auth_token=***`。

### 5.7 D7 载荷形态与投放（**与 ark 的最大差异点**）

| 项 | 决策 |
|---|---|
| 载荷内容 | `opencode.mjs` + `assets/**`（内嵌 UI）+ `opencode-server.js` + `lib/*` + 插件物化产物，打包为**单 `opencode-dist.tar.gz`（ustar）**放入 `app/src/main/assets/` |
| 解包执行者 | **Node 侧自解包**（沿用库「谁写谁读」纪律）：`bootstrap → appEntry` 先跑 `payload/unpack.js`，校验 marker（源 tar 的 SHA-256）→ 流式解到 `filesDir/opencode-dist/` → 原子写 `.manifest.json` → 再 import 业务入口；marker 命中即跳过（幂等，升级=换 marker） |
| 首启代价 | 解包 89+ 条目（秒级）+ `node::Start`（🔶 亚秒）+ 大 bundle import（⬜ 2–6 s 估）；加载页阶段文案覆盖 |
| 免解包优化（Phase 2 评估） | `android:extractNativeLibs` 与 AAB 无关；JS 无「resfile 等价物」，**除非**改用 `SEA`/fd 方案 —— 登记为实验项，不入主线 |
| 大包分发 | 侧载 APK 主线（无体积硬限）；若走 Play：AAB + **Play Asset Delivery（install-time pack）** 承载 tar.gz，`AssetPack` 首启拷入 `filesDir` 再走同一解包 marker |
| 体积预算 | 载荷压缩 ≈35 MB / 解压 80–110 MB；`libnode.so` ≈100–130 MB（AAR 压后 35–45 MB）；APK 合计 ≈90–150 MB（⬜ 实测，附录 C） |

### 5.8 D8 SQLite：`node:sqlite` 零补丁

`libnode.so` 内置 `node:sqlite`（ark 已用二进制证据判定 ✅；Android 引擎同一上游构建管线）。DB 落 `filesDir/data/opencode/opencode.db`（WAL）。P0-B 仅复验运行期：建库 → WAL → 写读回 → 并发会话。`better-sqlite3` 不引入（无 ABI 137 构建产物，且无必要）。

### 5.9 D9 环境契约（`NodeRuntimeOptions.env`，谁设什么）

| 变量 | 值 | 理由 |
|---|---|---|
| `HOME` / `USERPROFILE` | `<filesDir>` | 库默认重定向；`homedir()` 必须可写 |
| `TMPDIR`/`TMP`/`TEMP` | `<filesDir>/tmp` | 系统tmpdir 不可依赖；bootstrap 里 monkey-patch `os.tmpdir()` |
| `NODE_OPTIONS` | 清空 | 库默认；防宿主环境污染；`execArgv` 保持为空（R2 教训） |
| `XDG_DATA_HOME` / `XDG_CACHE_HOME` / `XDG_CONFIG_HOME` / `XDG_STATE_HOME` | `filesDir/{data,cache,config,state}` | opencode 全局根定位（`global-roots.ts`） |
| `OPENCODE_DB` | `<filesDir>/data/opencode/opencode.db` | 显式 DB 路径 |
| `OPENCODE_DISABLE_CHANNEL_DB` / `OPENCODE_DISABLE_MODELS_FETCH` / `OPENCODE_FILEWATCHER_DISABLE` / `OPENCODE_DISABLE_FFF` | `1` | 与 ark 同：watcher 无原生件、FFF 需 FFI、起步不依赖外网 |
| `OPENCODE_SERVER_PASSWORD` | `<connection.json 中的密码>` | 鉴权（§5.6） |
| `OPENCODE_NODE_ASSETS_DIR` | `<filesDir>/opencode-dist/assets` | 内嵌 UI 归档读取点 |
| `OPENCODE_CLIENT` | `desktop` | 与上游 desktop 一致 |
| `NO_PROXY`/`no_proxy` | `127.0.0.1,localhost,::1` | 本机直连 |
| `PATH` | 前置 `/system/bin` | `bash` 工具找 `sh`/toybox（§8.2） |
| `npm_config_registry`（可选） | 用户可配镜像 | pnpm/模型下载的国内网络适配 |

**cwd 规则**：`chdir(<filesDir>/workspace/<当前项目>)`（import 之前）。opencode 项目语义由进程工作目录决定（🔶 ark 真机结论：cwd=`/` 时 `/api/fs/*` 直接失败）。

### 5.10 D10 上游补丁：自有 `patches/v2.1.2/`，对标 ark 五件套

基线 `Branch_v2.1.2`（tag `v2.1.2`）。补丁**与 ark 同名同序**（便于逐条对照），内容按 Android 需要微调：

### 5.13 D14 工作区：沙箱 + SAF 导入/导出

- 默认项目根：`filesDir/workspace/`（多项目并列，`workspace/<name>/`）。

- 大仓库导入的成本显式提示（字节进度 + 可取消）；不做后台同步（v1）。
- 补丁 0007 的 UI 选择器经 `oc-plugin-workspace-roots` RPC 列举：**沙箱项目列表 / 导入新项目 / 删除项目**三动作，不暴露任意路径。
- 明确不申请：`MANAGE_EXTERNAL_STORAGE`、`READ_MEDIA_*`、`QUERY_ALL_PACKAGES`（§10）。

### 5.14 D15 后台与保活（Android 能力增量，Phase 3）

### 7.3 host 侧门禁（与设备同代 Node）

## 9. 上游补丁策略

纪律（沿用 ark §9）：幂等判据 `git apply --reverse --check`；新补丁不落入既有补丁上下文区间；追加到列表末尾；正反向往返 SHA-256 还原；换基线新建 `patches/<新 tag>/`。基线守卫与「共用 submodule 串行」见 §5.10。

v1 补丁集 = ark `patches/v2.1.2/` 五件套同名移植（0001 / 0003 / 0006 / 0007 / 0008，见 §5.10 表）。**不搬** ark 已取消项（0002/0004 SQLite、0005 string-width）。与 ark 的两处预期差异：
1. 条件变体名：0001 注入的条件名（`ohos`）在 Android 侧无 `.android.ts` 变体文件 ⇒ 仅需 `conditions` 顺序与 `node24` target 两处生效，其余 hunk 可能天然无操作 ⇒ 允许裁剪 hunk 但**保持补丁名与意图不变**，README 记录与 ark 的 hunk 级差异；
2. 0007/0008 的壳侧 RPC 能力名一致（`workspace.roots` / `git.credentials`），宿主实现从 ArkTS 换 Kotlin（§6 #10）。

# ④ 端到端取证（四通道）
adb exec-out screencap -p > s.png                                                     # 看
adb shell input tap <x> <y>                                                           # 点
adb forward tcp:4096 tcp:<port> && curl -s -u opencode:<pwd> http://127.0.0.1:4096/global/health   # 服务端
adb logcat -d | grep -E "node-bridge|OCDesktopAndroid|FATAL"                          # 日志
